- 用户新需求 + 选型：`qg rm [branch]`，`-o/--origin` 连远程分支一起删（push origin --delete），命令名 rm。
- `internal/git/rm.go`：porcelain 首条为主工作树；分支检出于主仓库→先切默认分支（defaultLocalBranch 排除自身，优先 main 后 master）；链接工作树→git worktree remove（脏树默认拒绝）；`branch -d` 防未合并丢码，--force 升级 -D + worktree remove --force；远程删除失败仅警告。所有 git 操作在主工作树根执行，shell 站在被删目录也不受影响。

## qg wt 指定起点分支（2026-11-08）

- 用户需求：新分支不应基于当前分支，而应基于指定分支（如线上 release）——标准开发流程。
- 实现：`qg wt <branch> --from <起点>`；起点解析 resolveStartPoint：先 `git fetch origin <ref>` 取线上最新 → 用 origin/<ref>；远端不存在回退本地分支；都没有报错。允许写 origin/release 形式。
- 默认起点：qg.hjson 新增 wt.base 配置（build.Config.Wt.Base + WorktreeBase() 助手，读取失败仅告警）；优先级 --from > wt.base > 当前 HEAD。
- CreateWorktree 签名改为 (branch, startPoint) 返回 (path, resolvedStart, error)。
- e2e 验证：bare origin + release 分支，站在 feat/a 上 --from release，feat/b 内容含 release 的 hotfix.txt 不含 feat/a 的 work.txt；故意删掉 origin/release 远程跟踪引用证明 fetch 真实生效；起点不存在报错清晰。
- 踩坑：一次 Edit 误删了 EntryFor 注释与函数签名之间的换行导致语法错误，已修复。
